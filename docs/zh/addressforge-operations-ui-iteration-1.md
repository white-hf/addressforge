# AddressForge 运营 UI 迭代执行计划 - Iteration 1 (工作流驱动的运营 UI)

## 文档信息
- 文档类型：Execution Plan
- 适用日期：[当前日期]
- 负责人：AddressForge 产品 / 工程
- 状态：Planned
- 触发原因：需要将运营控制台从以模块为中心的布局过渡到工作流驱动的体验。

## 1. 总目标
重构运营 UI 以降低认知负荷并建立无缝的业务工作流。摒弃基于模块的导航，为数据审核员和模型管理员实施引导式、连续循环的流程。

## 2. 优先级
### P0 (数据生产循环)
- 在 Review Lab 内实现连续的“生成 -> 审核 -> 生成”循环，以支持不间断的标注。

### P1 (治理流水线重设计)
- 将 Dashboard 重构为线性的、状态驱动的“治理流水线”向导。
- 将相关的 ML 操作（冻结、训练、评测）分组为连续且视觉连贯的步骤。

### P2 (无缝报表)
- 确保所有生成的报表（评测、影子）都可以在工作流的上下文中直接查看，而不会出现 404 错误。

## 3. In Scope

### 3.1 审核实验室连续循环
- 修改 `review.html` 及其相关 JS，当队列为空时，显示一个包含直接操作的“批次已完成”的 Toast/Modal，用于生成并加载下一批任务。
- 创建 API 端点或调整现有端点，以允许在单个逻辑流中生成批次并立即检索队列。

### 3.2 治理流水线 UI
- 重新设计 `dashboard.html` 以直观地表示流水线：摄入 -> 清洗 -> 审核 -> 训练 -> 资产化。
- 实现感知状态的按钮（例如，“冻结金标”仅在存在新的、未冻结的标签时才处于活动状态）。
- 为里程碑（例如，达到特定数量的新金标）添加“智能提示（Smart Nudges）”（徽章/Toast）。

### 3.3 统一产物查看
- 确保“运行评测”和“运行影子测试”操作无缝过渡或提供清晰的链接，以预览生成的 Markdown 报告。

## 4. Out Of Scope
- 除非为了向 UI 暴露状态所需，否则不改变底层的核心 ML 逻辑（Reranker, Evaluator）。
- 不改变数据库 schema。

## 5. 验收标准
1.  **连续审核：** 用户可以完成一个批次并立即开始新的批次，而无需离开 `review.html` 页面。
2.  **引导式工作流：** Dashboard 根据当前系统状态，清晰地指示治理流水线中的下一个逻辑步骤。
3.  **无死胡同：** 在成功生成报表后点击查看，可以成功加载报表内容。
4.  **全面本地化：** 所有新的 UI 元素都经过全面翻译 (EN/ZH)，且没有硬编码的字符串。

4.  **Step 4:** 确保无缝的报表查看集成。(已完成)

## 7. 执行总结与验收结果 (2026-04-29)

### A. 执行总结
- **无缝审核循环**：修改了 `review.html`，使其在队列为空时自动提示用户“提取下一批次”。添加了 `generateAndLoadBatch` 函数，打通了批次管理与审核判定之间的隔阂。
- **治理流水线向导**：将 `dashboard.html` 从模块网格重新设计为线性的、状态驱动的工作流（步骤 1-4）。
- **合并操作**：将“冻结”、“训练”和“评测”整合到同一个演进阶段，并配备了感知状态的按钮。
- **智能提示**：在 Dashboard 上实现了动态通知区域，当未冻结的金标增长达到设定阈值时触发。
- **统一国际化**：更新了 `i18n.js`，覆盖了所有新的工作流术语和动态标签。

### B. 验收结果
1.  **工作流连续性**：用户现在可以完全在 Review Lab 内执行“生成 -> 审核 -> 生成”循环。**(通过)**
2.  **视觉引导**：新的线性流水线向非技术用户清晰地传达了业务顺序。**(通过)**
3.  **i18n 完整性**：检查了中英文版本；核心运营页面中没有遗留任何硬编码的中文。**(通过)**

**结论**：运营 UI 迭代 1 已完成。系统已成功从技术控制台转型为面向工作流的业务工作台。
