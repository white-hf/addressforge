# AddressForge 运营子系统产品需求文档 (PRD)

## 1. 产品愿景与定位
AddressForge 运营子系统是一个“人机协作 (Human-in-the-loop)” 工作台，旨在将杂乱的地址字符串转化为规范、机读的商业资产。

**解决的核心问题：** 之前的 UI 是按技术模块（例如：看板、审核、批次、报表）组织的，迫使运营用户记住复杂的依赖关系（摄入 -> 清洗 -> 批次 -> 审核 -> 冻结 -> 训练 -> 评测 -> 影子测试 -> 提升）。这导致了很高的认知负荷和工作流的碎片化。

**新定位 (工作流驱动)：** 子系统将从“功能控制台”过渡到“引导式工作流工作台”。它将优先考虑业务目标（“我下一步该做什么？”）而非系统能力，实现海量数据标注和高级 ML 模型演进的无缝执行。

## 2. 核心用户画像与工作流

### 2.1 数据审核员 (主循环)
**目标：** 快速裁决有歧义或低置信度的地址。
**工作流：**
1.  **生成审核批次：** 系统自动拉取最有价值（低置信度 / 高频错误）的样本。
2.  **专家裁决：** 使用三栏式审核实验室（带有 AI 洞察）来确认或纠正地址。
3.  **连续循环：** 完成一批后，系统立即提示生成下一批，而无需返回中央看板。

### 2.2 模型管理员 (里程碑分支)
**目标：** 安全地演进核心解析引擎并部署新模型。
**工作流：**
1.  **监控增长：** 观察新金标的积累情况。
2.  **触发演进：** 达到阈值（例如 500 个新标签）时，冻结金标快照并触发 `ParserRerankerTrainer`。
3.  **发布准入检查：** 审查自动生成的影子和评测报告。
4.  **提升：** 如果指标（F1、回归风险）通过硬性准入，则将模型提升为活动状态。

## 3. 关键特性与信息架构 (IA) 重设计

### 3.1 统一的“治理流水线” (替代 Dashboard)
登录页将转变为线性的、状态驱动的向导。
- **可视进度：** 展示从数据摄入 -> 清洗 -> 审核 -> 模型演进 -> 资产化的流程。
- **上下文操作：** 按钮根据系统状态动态启用/高亮显示。（例如，“冻结并训练”仅在存在未冻结的金标时突出显示）。
- **智能提示：** Toast 通知或徽章指示何时达到里程碑（例如，“有新的金标数据可用于训练”）。

### 3.2 无缝审核循环 (Review Lab 增强)
- **批次结束提示：** 当审核队列达到 0 时，将出现模态框/Toast：“*批次已完成！您生成了 X 个金标。[生成下一批]*”。这消除了导航回“批次管理”模块的需要。

### 3.3 抽象化后台复杂性
- **整合的 ML 操作：** “冻结金标”、“训练模型”和“运行评测”步骤将在视觉上分组或排序，如果用户选择“自动演进”路径，则减少了用户手动独立触发每个步骤的需要。
- **原位报表查看：** 影子和评测报告可以直接从流水线视图或报表中心预览，而不会出现 404 死胡同。

## 4. 非功能性需求
- **国际化 (i18n)：** 在所有文本节点、占位符和动态状态消息中 100% 支持双语 (EN/ZH)。模板中没有硬编码的中文。
- **反馈即时性：** 所有操作（任务调度、批次生成）必须提供即时的、非阻塞的视觉反馈（Toast 通知）。
- **优雅降级：** 如果 LLM Refiner 失败或不可用，Review Lab 必须平滑降级到启发式解析结果，而不能破坏 UI。

## 5. 成功指标
1.  **工作流连续性：** 完成“生成 -> 审核 -> 生成”循环所需的页面重载次数为 0。
2.  **认知负荷降低：** 运营用户可以执行完整的模型训练和发布周期，而无需查阅技术文档。
3.  **UI 一致性：** 混合语言内容或未映射的 `data-i18n` 键的出现次数为 0。
